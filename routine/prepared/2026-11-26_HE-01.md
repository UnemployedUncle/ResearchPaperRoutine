## 1. 3분 복습
동일한 LLM으로 만든 두 문서 검증 Agent가 모두 정상 사례에서는 결과를 생성하지만, 하나는 접근 권한이 없는 문서를 요청하면 오류로 종료되고 다른 하나는 요청을 차단하고 사용자에게 안내합니다. 이 차이를 설명하려면 모델 자체와 실행 환경 중 어디의 어떤 기능을 확인해야 할까요? 한 문장으로 회상하세요.

- 확인 범위: PDF 인쇄 3쪽 §2.1 Definition and Genealogy 첫 정의 및 마지막 문장, 인쇄 4쪽 §2.2 What a Harness Is Not 첫째 항목. 오늘 버전 지정 PDF에 직접 접근하여 텍스트와 두 페이지 이미지(0-based 2, 3)를 확인했습니다. Figure 1과 Table 1은 HE-02에 남겨 둡니다.

**① 5분 — 3쪽 §2.1 첫 정의.** 모델과 하네스의 관계를 설명하는 첫 문장을 읽고, 모델 바깥에 놓이는 기능의 예시를 두 개 표시하세요. 마지막 문장에서 저자들이 기존 정의에 무엇을 더하여 연구 대상으로 삼는지도 확인합니다.

**핵심 개념 1: Scaffold (구조적 뼈대).** 반복 실행 루프나 도구 등록 구조처럼 Agent의 동작을 구성하는 코드의 뼈대입니다.
**핵심 개념 2: Harness (실행 환경).** 이러한 구조를 내장해 모델이 외부 환경에서 실제 작업하도록 만드는 실행체입니다. 논문은 두 용어가 실무에서 거의 동의어로 쓰이기도 한다고 설명하므로 절대적인 구분으로 외우지 않습니다.

**② 9분 — 4쪽 §2.2 첫째 항목.** Mini-SWE-Agent와 Claude Code를 대비하는 부분을 읽으세요. 어떤 것은 구조 코드의 사례이고 어떤 것은 실행 제품의 사례인지 구별합니다. 제품에 추가로 등장하는 기능을 원문에서 찾아 표시한 뒤, 왜 코드 길이만으로 운영 가능성을 판단하기 어려운지 생각해 보세요.

**③ 6분 — 설계 관점 연결.** 다음 가상 문서 검증 Agent의 세 상태를 비교하고, 원문 정의를 근거로 각 상태의 차이를 자신의 말로 정리하세요.
- A: 모델 호출과 문서 조회 도구의 반복 루프가 동작한다.
- B: A에 사용자 인터페이스와 권한 정책이 추가된다.
- C: B가 실제 사용자 업무에서 오류 상황을 포함한 인수 테스트를 통과한다.

A가 기본적인 Harness가 될 수 없다는 뜻은 아닙니다. B와 C는 운영 요구사항과 실행 검증을 추가한 실무 예시입니다. 저자는 구조를 비교했지, 기능을 추가하면 반드시 성능이나 안전성이 향상된다는 인과관계를 입증한 것은 아닙니다. 오늘은 원문의 용어 구분과 운영 준비도를 분리하는 것이 목표입니다.
