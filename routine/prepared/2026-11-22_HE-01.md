## 1. 3분 복습 | 같은 모델이면 같은 Agent인가?

**회상 질문 하나:** 동일한 LLM에 같은 파일 수정 과제를 주더라도, 하나의 실행 환경은 파일 변경 전 승인을 요청하고 다른 환경은 바로 도구를 호출합니다. 이 차이가 모델의 추론 능력 때문인지 실행 환경 때문인지 판단하려면 **어떤 증거를 먼저 확인**해야 할까요?

기억나는 Harness의 구성 요소 중 하나를 떠올린 뒤, 그 요소가 모델 출력을 실제 행동으로 바꾸는 지점을 예상하세요.

**① 5분 — 인쇄 1쪽, Abstract: 이 논문이 무엇을 비교했는가?**

첫 단락에서 모델과 Harness의 역할을 가르는 문장을 찾아 표시하세요. 저자들은 Harness를 반복 실행, 도구, 컨텍스트, 안전 제어, 조율, 확장 기능 등을 통해 LLM을 외부 세계와 연결하는 실행 환경으로 다룹니다.

**핵심 개념 1 — Harness(에이전트 실행 환경):** 모델이 생성한 판단·도구 요청을 실제 행동으로 연결하는 런타임입니다. 모델 파라미터와 분리해 보아야 하는 구성입니다.

Abstract에서 **11개 코딩 Agent Harness**와 비교 참고 대상으로 추가한 **Omnigent(메타 하네스)**를 어떻게 구별하는지 확인하세요. 그리고 저자들이 이 연구가 **성능 순위나 벤치마크가 아니라 구성 방식에 대한 비교**라고 밝힌 문장을 표시하세요. 숫자나 기술 이름을 전부 외우지 않아도 됩니다.

**② 9분 — 인쇄 2쪽, §1 Introduction 첫째·둘째 문단: 왜 새로운 연구가 필요한가?**

§1 첫 문단에서 기존 연구에 부족했던 것이 **실제 운영 시스템의 소스 코드에 근거한 공통 구조 설명**인지 확인하세요. 이어 둘째 문단에서 저자들이 기존 문헌을 어떻게 분류하는지 표시하세요.

**핵심 개념 2 — Source-code anatomy(소스 코드 구조 분석):** 실행 중 성능 수치를 비교하는 대신, 프로그램의 루프·도구·권한·컨텍스트 관리가 코드상 어떻게 구성되어 있는지 비교하는 연구 접근입니다.

**③ 6분 — 인쇄 2쪽, §1 세 번째 문단의 앞부분: 관찰 대상의 범위를 식별하기**

실제 조사 대상을 나열한 문단을 읽고 다음 세 가지 표시를 해보세요.

- 주요 모델 제공사에서 제공하는 Harness와 공개 소스 Harness를 구분하는 단어
- 분석 대상 코드의 시점이 **July 2026 releases**라는 문장
- 11개 시스템과 별도로 분석하는 12번째 조율 계층의 위치

**관찰 질문:** 이 시스템들이 모두 **같은 모델·같은 작업·같은 실행환경**에서 평가되었다는 뜻인가요? 이 논문의 설계가 뒷받침하는 주장과, 추가적인 통제 실험이 필요한 주장을 가려보세요.

**저자 주장:** Agent를 이해하려면 모델 이외의 실행 구조를 분석해야 한다는 문제의식입니다. **실제 연구 범위:** 특정 시점에 고정한 시스템들의 소스 코드 비교입니다. **실무 연결:** 기업용 Agent를 평가할 때 모델 선택표와 실행 환경 설계 검토표를 구분하자는 제안이며, 논문이 직접 실험한 생산성 효과는 아닙니다.
