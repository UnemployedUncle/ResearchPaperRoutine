# 2026년 11월 27일(금, 한국) | Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems | HE-01 | 핵심 질문: 동일한 LLM을 쓰는 Agent의 성능 차이가 Harness 설계 때문이라고 주장하려면 어떤 증거가 필요한가?

HE-01의 명시적 독서 완료는 확인되지 않았습니다. 오늘은 같은 차시의 범위 확인 부분인 §15.6에 집중해, 구조를 관찰하는 연구와 실제 성능을 측정하는 실험을 구분합니다. 밀린 과제는 추가하지 않습니다.

## 1. 3분 복습
지난 학습에서 코드의 뼈대(Scaffold)와 실제 실행 환경(Harness)을 구분했습니다. 두 Agent 중 한쪽에만 권한 검사 코드가 있다는 사실을 발견했다면, 그 사실만으로 해당 Agent가 실제 업무에서 더 안전하다고 결론 내릴 수 있을까요? 한 문장으로 답하고 그 이유를 생각해 보세요.

**① 6분 — 66쪽 하단, §15.6 도입부와 첫 실질 문단.** 저자들이 직접 수행한 분석과 인용한 벤치마크 수치의 출처를 구별하는 표현을 찾아 표시하세요.

핵심 개념 1: **Source-code analysis (소스 코드 분석).** 프로그램의 구현을 읽어 구조, 기능, 실행 조건을 파악하는 방법입니다. 구현이 존재한다는 근거를 얻을 수 있지만 운영 중의 성공률이나 속도를 그 자체로 측정하지는 않습니다.

**② 8분 — 66쪽 마지막 문단에서 67쪽 중간까지 §15.6.** 정성적 분류에 판단이 개입한다는 설명, 분석 코드의 버전 고정, Claude Code 소스 스냅샷의 재현성 한계를 확인하세요. 마지막 문단에서 연구진이 모든 시스템에 대해 수행하지 않은 비교가 무엇인지 찾습니다.

핵심 개념 2: **Controlled comparison (통제 비교).** 비교하려는 설계 요소 외의 조건을 가능한 한 동일하게 두고 실행 결과를 비교하는 방법입니다. 모델·업무·데이터·도구 접근 조건을 고정하면 Harness 변경의 효과를 더 명확히 살펴볼 수 있습니다.

**③ 6분 — 원문을 근거로 다음 가상 주장 세 개를 분류하세요.**

| 가상 주장 | 필요한 증거(직접 작성) |
|---|---|
| A의 코드에는 도구 실행 전 권한 검사가 있다. | ______ |
| A는 B보다 문서 검증을 빨리 완료한다. | ______ |
| 권한 검사 방식의 변경 때문에 실패율이 감소했다. | ______ |

어떤 주장이 코드 읽기로 확인 가능한지, 어떤 주장이 실행 측정 또는 통제된 변경 실험을 요구하는지 구분하세요. 이 표는 학습용 가상 사례이며 논문의 실험 결과가 아닙니다. 논문이 수행한 것은 특정 시점의 구조 비교이며 동일 조건의 성능 비교가 아닙니다.
