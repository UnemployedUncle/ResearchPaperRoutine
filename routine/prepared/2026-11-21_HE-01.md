**2026년 11월 21일(토, 한국) | Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems | HE-01 | 핵심 질문: 코드에서 관찰한 Harness 구조와 실제 성능·안전성에 대한 증거는 어떻게 구분할까?**

HE-01을 읽었다는 새로운 사용자 완료 확인이 없어 같은 차시를 유지합니다. 오늘은 이미 살펴본 Harness의 정의를 **“구조로 확인할 수 있는 사실”과 “실행 시험이 필요한 주장”**으로 구분해 읽습니다. 이전 RAG-01 완료는 별도 이력에 보존하고, RAG-02는 미완료·보류 상태입니다.

## 1. 3분 복습 | 실행 코드가 있다는 것과 실행이 검증되었다는 것

**회상 질문 하나:** 두 코딩 Agent가 같은 LLM을 사용하지만 한쪽에만 파일 삭제 전 승인을 확인하는 코드가 있습니다. 코드를 읽었다는 사실만으로 “이 Agent는 미승인 삭제를 절대 하지 않는다”고 결론 내릴 수 있을까요?

**원문에서 확인할 근거**와 **실제 실행 테스트가 필요한 항목**을 각각 한 가지 떠올려 보세요.

## 2. 20분 원문 읽기 | 구조 분석과 실행 측정 사이의 경계

**고정 원문:** [PDF — arXiv:2609.00006v1](https://arxiv.org/pdf/2609.00006v1) · [공식 등록 정보](https://arxiv.org/abs/2609.00006)

**서지 구분:** arXiv v1 최초 제출은 **2026년 7월 15일**입니다. 초록이 언급하는 2026년 4월 연구는 이전 판본/연구이며 이번 arXiv v1의 후속 수정본이라는 뜻은 아닙니다. 읽는 버전을 바꾸지 않습니다.

**① 8분 — 4쪽 §2.2: 평가를 담당하는 계층을 정확히 찾기**

먼저 *A harness is not an evaluation harness* 항목을 찾으세요. 저자는 SWE-bench 평가 하네스가 **완성된 agent를 감싸 과제에서 시험**하는 반면, agent harness는 **model을 감싸 실제 행동을 가능하게 한다**고 구분합니다. 이어 *A harness is not an orchestrator*에서 상위 조율자가 직접 편집 루프를 갖지 않는다는 경계를 확인하세요.

**핵심 개념 1 — Agent harness:** LLM의 출력을 반복 루프, 도구, 컨텍스트 및 실행 통제에 연결하는 런타임. 도구를 호출할 수 있다는 *구조적 능력*과 호출 결과가 실제로 옳거나 안전하다는 *실증적 성과*는 다른 판단입니다.

**관찰 지점:** §2.2의 두 항목을 읽으면서 “모델을 행동하게 하는 층 / 완성된 Agent를 외부에서 시험하는 층 / 여러 실행체를 조율하는 층”을 각각 분리하세요. 코드 내부에 자체 테스트 명령이 있다는 사실만으로 외부 평가 하네스와 같다고 보지 마세요.

**② 7분 — 66쪽 §15.6: 저자가 실제로 검증하지 않은 것은 무엇인가?**

**핵심 개념 2 — Threats to Validity(타당도 위협):** 연구에서 확인한 관찰이 어떤 종류의 주장까지 뒷받침하고, 어떤 주장은 연구 설계 때문에 뒷받침하지 못하는지 밝히는 대목입니다.

§15.6 도입 직후 저자들이 **source-code reading**을 했지만 **runtime measurement**를 하지 않았다고 설명하는 문장을 표시하세요. 이어 논문에 등장하는 benchmark 수치가 **각 시스템의 자체 문서**에서 왔다는 표현을 찾으세요.

**원문 관찰 질문:** 저자가 “시스템이 어떻게 구성되어 있는지”를 안다고 주장하는 것과 “얼마나 빠른지”를 안다고 주장하는 것의 차이는 무엇인가요? 본문의 아키텍처 비교를 같은 모델·같은 과제에서 수행한 head-to-head 성능 시험처럼 읽지 마세요.

**③ 5분 — 두 절을 연결해 증거 수준 분리하기**

아래 가상 계약서 Agent 예시는 논문 실험이 아닙니다. 빈 칸을 직접 판단하세요.

| 설계 검토 문장 | 원문 읽기로 판단할 것 |
|---|---|
| “권한 검사 코드와 승인 분기점이 있다” | 코드 구조에서 관찰 가능한가? 어느 부분을 읽어야 하나? |
| “미승인 메일은 언제나 차단된다” | 실행 테스트에서 어떤 반례를 시험해야 하는가? |
| “A Agent가 B Agent보다 20% 빠르다” | 같은 조건의 측정 자료가 없는 이 논문에서 주장할 수 있는가? |

**저자의 주장:** 소스 코드에서 하네스 구성과 설계 선택을 기술·비교할 수 있다는 것입니다. **실험 근거의 한계:** 동일 조건의 실행 성능이나 특정 보안 정책의 완전성을 검증한 연구는 아닙니다. **실무 제안:** 코드 구조 검토와 시나리오 기반 실행 평가를 별도 증거로 관리하세요.
