**2026년 11월 13일(금, 한국) | Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks | RAG-02 | 핵심 질문: 이미 학습된 DPR과 BART를 결합한 뒤, 정답 문서를 따로 표시하지 않아도 RAG를 학습할 수 있는 이유는 무엇인가?**

RAG-01의 독서 완료는 확인되었으나 **RAG-02 완료 확인은 아직 없습니다.** 오늘은 이전 차시의 입력 \(x\)·문서 \(z\) 구분을 복습한 뒤, **DPR의 초기 검색 능력과 BART의 초기 생성 능력을 어디서 얻었는지** 원문으로 확인합니다. 어제 자료를 밀린 과제로 더하지 않습니다.

## 1. 3분 복습 | 역할을 구분하는 질문

**회상 질문 하나:** DPR이 관련 문서 Top-K를 찾고 BART가 답변을 생성한다는 구조를 이해했다면, **처음부터 새 프로젝트의 계약서와 질문을 모두 학습해야만 이 두 구성요소를 사용할 수 있을까요?**

답을 떠올릴 때 '이미 학습된 능력으로 시작하는 것'과 '새 업무 데이터에 맞춰 추가 학습하는 것'을 구별해 보세요.

## 2. 20분 원문 읽기 | 사전학습, 초기화, 추가 학습의 경계

**원문:** [Lewis et al., RAG PDF — 고정 버전 v4](https://arxiv.org/pdf/2005.11401v4) · [arXiv 제출 및 수정 이력](https://arxiv.org/abs/2005.11401). **최초 발표 2020-05-22(v1), 오늘 읽는 수정본 2021-04-12(v4)**. 읽을 위치는 **PDF/인쇄본 2쪽 Figure 1, 3쪽 §2.2 “Retriever: DPR”, §2.3 “Generator: BART”, §2.4 “Training”의 시작 문장**입니다. 해당 페이지의 실제 그림과 문장을 확인했습니다.

**① 4분 — 2쪽 Figure 1에서 두 개의 ‘Pre-trained’를 찾아보기.** Figure 1의 설명에서 Retriever와 seq2seq Generator 모두 사전학습된 구성요소로 시작한다는 표현에 표시하세요. 그림 안의 Query Encoder·Document Index와 Generator를 나누고, **사전에 준비된 요소와 질문마다 새로 수행하는 요소**를 직접 적어 보세요. *Document Index가 존재한다*는 사실과 *새 업무 계약서가 인덱스에 반영되어 있다*는 사실은 같지 않습니다.

**② 9분 — 3쪽 §2.2 Retriever: DPR의 초기 능력.** 핵심 개념 **Pre-trained initialization(사전학습된 모델로 초기화)**은 모델을 무작위 상태에서 시작하지 않고 기존에 학습한 가중치로 출발하는 것입니다. 이 논문은 질문 인코더와 문서 인코더를 사용하는 DPR bi-encoder를 기반으로 검색기를 초기화하고 문서 인덱스를 구축합니다. §2.2 마지막에서 DPR이 **TriviaQA와 Natural Questions의 답이 포함된 문서를 찾도록 학습**되었다는 설명을 찾아보세요.

원문의 검색 분포 \(p_\eta(z\mid x)\propto \exp(d(z)^\top q(x))\)에서 \(x\)는 질문, \(z\)는 후보 문서, \(q(x)\)와 \(d(z)\)는 각각의 벡터입니다. 내적 점수는 **어떤 문서가 질문에 더 잘 맞는지**를 정하는 데 사용됩니다. 지금은 수식을 다시 외우기보다, **이 벡터화 능력을 어디서 가져왔는가**에 밑줄을 그으세요.

**관찰 질문:** 사전학습된 DPR을 사용했다는 사실이 새로 투입한 모든 계약서를 자동으로 검색할 수 있음을 보장할까요? 문서 인덱스에 무엇이 들어 있어야 하는지도 생각해 보세요.

**③ 7분 — 3쪽 §2.3 Generator: BART와 §2.4 첫 문장.** §2.3에서는 BART-large를 생성기에 사용하고, BART가 **denoising objective(손상된 입력을 복원하는 사전학습 목표)**로 사전학습되었다는 문장을 찾으세요. DPR이 주로 **질문과 관련 문서를 연결하는 능력**에서 출발한 것과 비교해 보세요.

이제 오늘의 두 번째 핵심 개념 **Retrieval supervision(검색 대상에 대한 직접 지도)**을 확인합니다. 이는 학습할 때 '이 질문에는 이 문서를 찾아야 한다'라는 정답 신호를 주는 방식입니다. §2.4의 첫 문장은, 저자들이 최종 RAG 모델의 Retriever와 Generator를 **검색할 정답 문서에 대한 직접 지도 없이 결합 학습**한다고 설명합니다. **정답 문서 지도가 없다는 뜻이지, 질문–정답 학습 데이터 자체가 없다는 뜻은 아닙니다.** 수식과 세부 학습 절차는 오늘 범위 밖입니다.

**관찰 질문:** DPR의 *사전학습 단계*에 사용된 검색 지도와, RAG의 *후속 학습 단계*에서 정답 검색 문서에 대한 직접 지도가 없다는 설명이 왜 서로 모순되지 않을까요? 두 단계의 학습 목적을 다르게 표시해 보세요.

오늘 읽은 부분은 논문의 **설계·학습 방법 설명**입니다. 이 구조만으로 기업 내부 문서를 정확하게 검색하거나 생성 결과를 검증한다는 실증적 결론을 내리지 마세요.

## 3. 5분 이해 기록 | 무엇을 사전학습에서 가져왔는가

| 기록 항목 | 직접 작성할 내용 |
|---|---|
| **핵심 주장 한 문장** | DPR과 BART가 각각 어떤 사전학습 능력을 갖고 출발하며, RAG가 이를 어떻게 활용하는가? |
| **근거가 있는 원문 위치** | Figure 1 캡션 또는 §2.2의 DPR 사전학습 문장, §2.3의 BART 사전학습 문장, §2.4의 첫 문장 중 선택 |
| **남은 질문 하나** | 정답 검색 문서의 라벨이 없어도 결합 학습이 가능한 이유에서 무엇이 아직 헷갈리는가? |

**자기 점검 1:** DPR의 사전학습에 질문·답변을 포함하는 문서 정보가 사용됐다는 사실과, §2.4에서 새로운 RAG 학습에 직접 검색 문서 라벨을 사용하지 않는다는 설명을 구분할 수 있나요?

**자기 점검 2:** *검색 인덱스에 최신 문서가 없음*과 *생성 모델이 검색 문서를 잘못 요약함*은 같은 종류의 문제인가요?
