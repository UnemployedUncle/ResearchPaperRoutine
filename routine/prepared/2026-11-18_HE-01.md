**2026년 11월 18일(수, 한국) | Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems | HE-01 | 핵심 질문: 개발 프레임워크를 도입하는 것과 실제로 작동하는 Agent Harness를 확보하는 것은 어떻게 다른가?**

현재 우선 논문은 Harness Engineering입니다. **HE-01 독서 완료가 아직 확인되지 않아 같은 차시를 유지**하고, 오늘은 §2.2의 *framework–harness 경계*를 좁게 복습합니다. RAG-01 완료 기록은 유지하고 RAG-02는 미완료·보류 상태입니다.

## 1. 3분 복습 | 코드를 가져다 쓰는 것과 실행 환경에 들어가는 것

**회상 질문 하나:** 한 팀이 Agent 라이브러리를 프로젝트에 설치했고, 다른 팀은 도구·승인·대화 기록이 이미 연결된 코딩 Agent에서 작업합니다. 두 팀 모두 “Agent를 도입했다”고 말할 때, **운영 책임은 정확히 어디서 달라질까요?**

모델 성능이 아니라 실행 루프, 도구 호출, 권한 설정 중 누가 구현·운영하는지를 한 문장으로 예상하세요.

## 2. 20분 원문 읽기 | Framework는 Harness와 동의어일까?

**고정 원문:** [PDF arXiv:2609.00006v1](https://arxiv.org/pdf/2609.00006v1) · [arXiv 등록·버전 이력](https://arxiv.org/abs/2609.00006). 현재 읽기 버전인 v1의 등록일은 **2026년 7월 15일**입니다. 논문은 2026년 4월의 이전 연구 판본을 언급하지만, 이를 별도의 arXiv 수정본(v2)으로 간주하지 않습니다.

**오늘의 실제 위치:** PDF/인쇄본 **3쪽 §2.1 “Definition and Genealogy”의 마지막 정의 부분과 하단 각주**, **4쪽 §2.2 “What a Harness Is Not” 중 scaffold 및 agentic framework 항목**. 두 페이지 원문 텍스트와 페이지 이미지를 확인했습니다. §2.3의 Figure 1과 Table 1은 HE-02용으로 남겨둡니다.

**① 5분 — 3쪽 §2.1: '작동하는 Agent'의 최소 정의 찾기.** 저자들이 Macedo의 정의를 채택한다는 문장에서, 언어모델을 감싸 **저장소에 행동할 수 있게 하는 계층**이 무엇인지 표시하세요. 이어 Agent = Model + Harness라는 설명을 찾아, *모델을 알고 있는 것*과 *모델이 실제 행동할 수 있는 상태*를 구별하세요.

첫 번째 핵심 개념 **Agent harness(에이전트 하네스)**는 모델 출력을 도구·실행 루프·안전 통제 등과 연결해 실제 업무를 수행하게 하는 **런타임**입니다. 모델 가중치나 프롬프트 하나를 가리키지 않습니다.

**② 9분 — 4쪽 §2.2: 프레임워크와 하네스의 두 문장에 밑줄 긋기.** “A harness is not an agentic framework” 항목에서 개발자가 **가져다 쓰는 라이브러리**와 개발자가 **그 안에서 일하는 런타임**을 나누는 표현을 찾아 보세요.

두 번째 핵심 개념 **Agentic framework(에이전트 개발 프레임워크)**는 라이브러리·API 같은 개발 구성 수단입니다. 이를 이용해 실행 시스템을 만들 수 있지만, **프레임워크를 설치한 것만으로 실행 환경·권한·도구·세션 운영이 끝난 것은 아닙니다**.

같은 항목의 마지막에서 저자들이 이 구분이 2026년 들어 두 방향에서 흐려지고 있다고 말한 이유를 생각하세요. 용어를 이분법으로 암기하는 대신 **제품이 '라이브러리로 쓰이는 부분'과 '작동하는 실행체'를 모두 제공할 수 있는지**를 판단하세요.

**③ 6분 — 3쪽 하단 각주 + 4쪽의 정의: 경계가 실제로 흐려지는 사례.** §2.1 하단 각주는 LangChain의 **Deep Agents**가 **LangGraph를 기반으로 만들어진 Harness**라고 설명합니다. 따라서 “프레임워크와 하네스는 서로 완전히 배타적이다”는 결론을 피하세요.

다음은 논문 실험이 아닌 **분류 연습**입니다.

| 상황 | 직접 분류할 질문 |
|---|---|
| 라이브러리를 import한 뒤 실행 루프와 승인 코드를 직접 구현 | 어떤 것은 제공받았고, 어떤 것은 직접 책임질까? |
| 설치된 코딩 Agent에서 파일 읽기·수정·승인을 수행 | 실제 작동하는 런타임은 어디에 있을까? |
| 프레임워크를 사용해 도구·루프·권한을 갖춘 서비스를 배포 | 하나의 시스템이 두 역할을 겸할 수 있을까? |

**근거 범위:** §2.2는 개념적·구조적 구분입니다. 저자들이 조사한 11개 코딩 하네스에서 범용 에이전트 프레임워크 사용이 관찰되지 않았다는 결과를 **모든 AI Agent가 프레임워크를 쓰지 않는다**는 일반 법칙으로 확대하지 마세요. 성능 우위도 이 절에서 실험한 것이 아닙니다.
