**2026년 11월 20일(금, 한국) | Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems | HE-01 | 핵심 질문: Agent가 실제로 행동할 수 있는 런타임을 갖췄는지 어떻게 판단할까?**

현재 논문의 **HE-01 독서 완료 근거는 아직 확인되지 않았습니다.** 따라서 진도를 올리지 않고, 기존 §2.1~§2.2를 새로운 관점인 **“정의에 맞는 실행체인가, 설계에 불과한가”**로 복습합니다. 하루 30분만 학습하며 밀린 과제는 추가하지 않습니다.

## 1. 3분 복습 | 모델의 제안과 실행체의 존재

**회상 질문 하나:** LLM이 “계약서 파일을 읽고 조건을 검증하겠습니다”라고 말했지만 실제로 파일을 여는 코드와 권한 검사가 없다면, 이것을 *작동하는 Agent Harness*라고 부를 수 있을까요?

답을 먼저 정하지 말고, **모델의 출력**과 **프로그램이 실제로 수행하는 작업**을 나누어 생각하세요.

## 2. 20분 원문 읽기 | Harness의 최소 조건과 경계

**원문:** [고정 PDF arXiv:2609.00006v1](https://arxiv.org/pdf/2609.00006v1) · [arXiv 원문·제출 이력](https://arxiv.org/abs/2609.00006).

**버전:** 최초 등록 2026년 7월 15일, 읽는 판본 v1(2026년). 이번 차시에서는 판본을 바꾸지 않습니다. **위치:** PDF **3쪽 §2.1 “Definition and Genealogy” 마지막 문단**, **4쪽 §2.2 “What a Harness Is Not”의 네 경계 항목**. 2026년 11월 20일에 공식 arXiv PDF의 이 두 쪽을 텍스트와 페이지 이미지로 확인했습니다. Figure 1은 보이지만 오늘의 독해 대상으로 해석하지 않습니다.

**① 6분 — PDF 3쪽 §2.1: 정의가 요구하는 실제 동작을 찾기**

저자들이 Macedo의 정의를 채택한다는 문장을 찾으세요. *언어모델을 감싸 저장소에 행동할 수 있는 Agent로 바꾸는 계층*이라는 의미를 자신의 말로 바꾸어 보세요.

첫 번째 핵심 개념인 **Agent Harness(에이전트 하네스)**는 모델 자체가 아니라 **모델을 실제 환경에 연결하는 실행 런타임**입니다. 원문이 열거하는 loop, tools, context, safety controls 등은 이 실행체의 범위를 이해하기 위한 단서입니다.

**관찰할 것:** §2.1에서 저자들이 **정의를 채택한 부분**과, 이후 **§2.3에서 하위 시스템을 분해하겠다고 예고한 부분**을 서로 다른 색으로 표시하세요. *개념의 정의*와 *실제 구현에 대한 분석*은 다른 층위입니다.

**② 8분 — PDF 4쪽 §2.2: 코드의 뼈대와 배포된 실행체 구분하기**

두 번째 핵심 개념은 **Scaffold(스캐폴드)**로, 문맥상 실행 루프와 도구 등록부 같은 **구조적 코드의 뼈대**를 말합니다. §2.2에서는 Scaffold와 Harness를 실무에서 거의 같은 뜻으로 쓰기도 하지만, 구분한다면 전자는 구조적 코드, 후자는 이를 담아 배포된 *runtime artifact*라고 설명합니다.

“A harness is not a scaffold—quite”와 “A harness is not an agentic framework” 두 항목에서 다음 표현을 찾아 밑줄 치세요.

- 무엇이 **structural code**이고 무엇이 **shipped runtime artifact**인가?
- 개발자가 **import하는 라이브러리**와 실제로 **그 안에서 작업하는 런타임**의 차이는 무엇인가?

이어 원문에서 Mini-SWE-Agent와 Claude Code가 어떤 점을 대비하는 예시로 등장하는지 찾으세요. **코드가 짧거나 시스템이 복잡한 것이 곧 성능 우위라는 뜻은 아닙니다.**

**③ 6분 — PDF 4쪽 §2.2: 경계 사례로 분류해 보기**

아래 세 사례는 **논문 실험이 아닌 독해용 가상 사례**입니다. 각 사례가 *프롬프트 / scaffold / 실행 harness* 중 어디까지 제공하는지 판단하고, 그렇게 판단한 이유를 §2.1 또는 §2.2의 문장에 연결하세요.

| 가상 구현 | 원문 기준으로 확인할 질문 |
|---|---|
| “파일을 수정해”라는 프롬프트만 제공 | 실제 저장소에 행동하는 런타임은 있는가? |
| 반복 실행 루프와 도구 등록 함수만 작성 | 구조 코드 외에 실제 작동 환경과 실행 제어가 있는가? |
| 모델·도구 실행·권한·작업 결과 전달을 연결 | 어떤 구성요소가 모델의 출력을 실제 행동으로 바꾸는가? |

마지막 1분에는 §2.2의 **evaluation harness** 및 **orchestrator** 항목을 짧게 다시 확인하세요. 평가 체계는 Agent를 감싸 시험하고, 상위 조율자는 하나 이상의 Harness를 조정하지만 자체 편집 루프를 수행하지 않는다는 구별을 찾습니다.

**근거 범위:** 저자들은 11개 코딩 하네스의 **소스 코드 구조**를 비교합니다. 위 가상 사례의 실제 성능, 안전성 향상, 기업 업무 생산성은 이 부분에서 실험으로 검증한 결과가 아닙니다.
