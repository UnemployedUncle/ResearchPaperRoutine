## 1. 3분 복습 | 모델에 요청하는 것과 실제로 실행하는 것

가상의 두 Agent를 비교해 보세요. A는 LLM에 “파일을 수정하고 테스트해 줘”라고 요청합니다. B는 같은 LLM을 사용하지만 파일 편집 도구, 테스트 실행, 실패 결과 전달, 실행 전 승인 절차를 연결합니다.

**회상 질문:** 같은 모델을 쓰는데도 두 Agent의 동작이 달라진다면, 그 차이를 설명하려면 모델 외에 무엇을 살펴봐야 할까요?

## 2. 20분 원문 읽기 | Harness의 정의와 경계

**원문:** [지정 PDF](https://arxiv.org/pdf/2609.00006) · [v1 PDF](https://arxiv.org/pdf/2609.00006v1) · [arXiv 논문 페이지](https://arxiv.org/abs/2609.00006).

확인한 판본은 **arXiv:2609.00006v1, 2026년**입니다. 원문 텍스트는 확인했지만 PDF 페이지 이미지 열람은 실패했습니다. 따라서 오늘은 페이지 번호나 그림 해석을 지정하지 않고 **Abstract, §1 Introduction 앞부분, §2.1 Definition and Genealogy, §2.2 What a Harness Is Not**을 기준으로 읽습니다.

**① 4분 — Abstract와 §1 Introduction: 무엇을 비교하는 연구인가?**

저자들은 11개 하네스와 별도의 메타 하네스 대조 사례를 소스 코드 관점에서 분석합니다. 읽을 때 제품 성능 순위가 아니라 구조의 비교라는 점을 표시하세요. [S1]

원문에서 찾아볼 질문은 하나입니다. **“이 연구의 관찰 단위는 모델의 정답률인가, 모델을 작동시키는 실행 시스템의 설계인가?”** 오늘은 제품별 수치와 구현 세부사항을 외우지 않습니다.

**② 8분 — §2.1·§2.2: 두 개념만 구별하기.**

**Harness(하네스)**는 모델을 둘러싸고 실제 작업을 가능하게 하는 실행 환경입니다. 이 논문에서는 실행 루프, 도구, 컨텍스트, 안전 제어, 오케스트레이션, 확장 기능 등을 포함합니다. 프롬프트 하나와 동일하지 않습니다. [S1, §2.1]

**Agentic framework(에이전트 개발 프레임워크)**는 에이전트를 만들 때 사용하는 라이브러리·구성 수단입니다. 저자들은 이를 실제로 작동하는 하네스와 구별합니다. 프레임워크로 하네스를 만들 수 있으므로 둘을 반드시 양자택일로 볼 필요는 없습니다. [S1, §2.2]

원문을 보고 아래의 빈칸을 본인의 말로 채우세요.

> 모델은 ______을 판단하고, 하네스는 그 판단을 ______할 수 있도록 실행 환경을 제공한다.

이후 §2.2에서 agent harness와 evaluation harness를 구분한 대목을 찾아, 각각 무엇을 감싸는지 확인하세요. 설명을 길게 확장하지 말고 한 줄씩만 기록합니다.

**③ 8분 — 정의를 가상의 실행 흐름에 대입하기.**

§2.1의 정의를 다시 읽은 뒤, 다음의 **설명용 가상 시스템**을 검토하세요. 논문에서 측정한 실험 결과가 아니라 책임을 분리하는 연습입니다.

| 상황 | 내가 구분할 책임 |
|---|---|
| 모델이 “계약서를 조회하자”고 제안한다 | 제안을 실제 조회 호출로 바꾸는 코드는 어디에 있어야 할까? |
| 도구 호출이 실패한다 | 오류를 모델에 돌려주고 재시도 횟수를 제한하는 것은 누구의 일일까? |
| 모델이 외부 발송을 제안한다 | 사용자 승인을 확인하고 미승인 실행을 차단할 위치는 어디일까? |

하나를 골라 **모델 제안 → 실행 조건 확인 → 도구 호출 → 결과 전달 → 다음 판단**의 순서에 대응시켜 보세요. 실제 프로젝트가 이렇게 구현되어 있다고 가정하지 마세요.

마지막으로 **§15.6 Threats to Validity의 첫 문단**을 짧게 확인합니다. 저자들은 소스 코드 분석과 런타임 성능 측정을 구분합니다. 따라서 설계가 관찰되었다는 것만으로 그 설계가 성능 향상의 원인이라고 단정할 수는 없습니다. [S1, §15.6]
