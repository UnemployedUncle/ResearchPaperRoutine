 
0️⃣ 한눈에 보는 독해 지도 (Reading Map)
논문을 읽기 전에 머릿속에 그려야 할 지도
•	이 논문이 답하려는 단 하나의 핵심 질문:
•	저자들이 세운 가설(hypothesis):
•	이 논문이 주장하는 결론 한 문장:
•	논문 전체 구조에서
o	가장 중요한 섹션:
o	상대적으로 스킵해도 되는 섹션:
➡️ 목적:
“어디에 집중해서 읽어야 하는지”를 먼저 결정
 
1️⃣ 연구 맥락과 문제 설정 (Why this paper exists)
1.1 당시 연구 커뮤니티의 상황
•	이 논문이 나오기 직전, 주류 접근법은 무엇이었나?
•	커뮤니티가 암묵적으로 받아들이던 가정은?
•	성능은 좋았지만 찝찝했던 부분은 무엇이었나?
1.2 기존 연구의 구조적 한계
단순 나열 ❌ → 구조적 문제 정의 ⭕
•	기존 방법들이 공통적으로 갖는 구조:
•	그 구조가 만들어내는 필연적 한계:
•	저자들이 “이건 근본적으로 잘못됐다”고 본 지점:
➡️ 여기서부터 논문의 모든 선택이 설명되기 시작함
 
2️⃣ 이 논문을 읽는 진짜 목적 (Reading Objectives)
이 논문을 왜 읽는지 독자의 목적을 명시
•	알고리즘 관점
o	새로운 알고리즘인가?
o	아니면 기존 알고리즘의 재구성/해석인가?
•	이론 관점
o	새로운 이론인가?
o	기존 이론을 다른 문제에 적용한 것인가?
•	실험/시스템 관점
o	모델 자체보다 실험 설계가 중요한가?
o	데이터셋/세팅이 핵심 기여인가?
➡️ 목적에 따라
“수식을 깊게 볼지 / 실험을 깊게 볼지” 결정
 
3️⃣ 저자들이 ‘증명하려고 한 것’의 구조
많은 논문은 사실상 논리적 증명 구조를 가짐
3.1 저자들의 논증 구조
•	Step 1: 기존 접근은 왜 실패하는가
•	Step 2: 우리가 제안하는 관점은 무엇이 다른가
•	Step 3: 그 관점이 맞다는 근거 (이론 / 실험)
•	Step 4: 그래서 어떤 결론이 나오는가
➡️ 이 구조를 이해하면 실험 결과가 갑자기 명확해짐
 
4️⃣ 방법론 전체 흐름 (Big Picture First)
수식 보기 전에 반드시 거쳐야 할 단계
•	입력은 무엇인가?
•	모델은 무엇을 예측하려는가?
•	중간에 어떤 추상화가 있는가?
•	출력은 무엇이며, 무엇이 달라졌는가?
📌 중요
이 단계에서 이해가 안 되면 → 수식은 절대 이해되지 않음
 
5️⃣ 핵심 수식 Deep Dive (독해 중심)
❌ “이 수식은 loss function이다”
⭕ “이 수식이 없으면 이 논문은 성립하지 않는다”
5.1 이 수식이 등장한 이유
•	저자들이 직면한 구체적인 문제:
•	기존 수식으로는 왜 해결이 안 됐는가?
5.2 변수 하나씩 다시 읽기
“수식 = 압축된 문장”
•	각 변수는 무엇을 의미하는가
•	모델 안에서 실제로 어디에서 나오고 어디로 가는가
5.3 직관적 설명 (Understanding Mode)
•	이 수식을 한 문장으로 말하면?
•	비유로 설명하면?
•	만약 이 수식을 제거하면 어떤 일이 벌어지는가?
5.4 관련 개념 리프레시 (Context Refresher)
독자가 헷갈릴 수 있는 지점 의도적으로 보완
•	Adam Optimizer:
o	왜 SGD 대신 Adam을 썼는가?
•	Beam Search:
o	Greedy와 무엇이 다른가?
•	Marginalization:
o	왜 평균을 내는가?
o	무엇을 “모른다고 가정”하는가?
•	DPR / BART:
o	이 논문에서의 역할은 무엇인가?
o	그냥 baseline인가, 구조적 핵심인가?
 
6️⃣ 실험 결과를 “이해”하는 방식
숫자보다 이유
6.1 실험은 무엇을 검증하려 했는가
•	가설과 실험의 1:1 대응 관계:
•	각 실험이 반박하려는 반대 주장:
6.2 결과가 이렇게 나온 이유
•	어떤 구성 요소가 성능을 만들었는가?
•	단순 성능 향상인가, 구조적 개선인가?
6.3 결과 해석 시 주의점
•	저자들이 숨긴 전제:
•	특정 데이터셋에만 유리한 이유는?
 
7️⃣ 이 논문의 한계는 어디서 오는가
한계는 실수가 아니라 선택의 결과
•	이 논문이 포기한 것:
•	이 가정이 깨지면 어떤 문제가 생기는가?
•	스케일, 도메인, 비용 측면의 제약:
 
8️⃣ 향후 연구 방향 (Research Continuation)
단순 “future work”가 아니라 연구 갈래 제시
•	이 논문이 연 문:
•	아직 열리지 않은 문:
•	후속 연구가 반드시 해결해야 할 질문들:
 
9️⃣ 관련 개념·논문 연결 지도
이 논문을 연구 트리 안에 배치
•	이 논문이 기반으로 삼은 핵심 논문 2–3편
•	이 논문 이후 등장한 대표 후속 연구
•	다른 도메인에서의 유사한 접근
 
🔟 최종 독해 요약 (Reader’s Takeaway)
•	이 논문을 읽고 반드시 가져가야 할 생각 3가지
•	이 논문을 다시 안 읽어도 되는 이유 / 다시 읽어야 하는 이유
•	우리 연구/프로젝트에 주는 가장 현실적인 시사점
 



✅ Workflow 제안 상세
🧭 Workflow 1. 논문 맥락 & 독해 목적 설정 (Reading Orientation)
해결하는 문제
•	“요약은 있는데 왜 읽는지 모르겠다”
•	“어디에 집중해야 할지 모르겠다”
역할
•	논문을 읽기 전 머릿속 독해 지도 생성
•	이 논문이 등장한 시대적·학문적 맥락 설명
산출물
•	핵심 질문 (1문장)
•	저자 가설
•	이 논문을 읽는 목적 (알고리즘/이론/실험 중 무엇인가)
•	집중해서 읽을 섹션 vs 스킵 가능 섹션
👉 이 workflow 없으면 이후 workflow는 방향을 잃음
 
🧠 Workflow 2. 저자 논증 구조 해석 (What are they trying to prove?)
해결하는 문제
•	“결과는 알겠는데 왜 그런 결론이 나왔는지 모르겠다”
•	“실험이 주장과 연결되지 않는다”
역할
•	논문을 논리적 증명 구조로 재구성
•	저자들이 실제로 증명하려는 것 정리
산출물
•	기존 연구의 구조적 한계
•	저자 논증 Step 1 → Step 4
•	실험이 각 Step을 어떻게 뒷받침하는지 연결
👉 이 workflow가 있으면 실험 결과 해석이 쉬워짐
 
🧩 Workflow 3. 방법론 Big Picture (Before formulas)
해결하는 문제
•	“수식을 보기 시작하자마자 막힌다”
•	“모델이 뭘 하는지 전체 그림이 안 잡힌다”
역할
•	수식 없는 상태에서 방법론 전체 흐름 설명
•	입력–처리–출력 구조 명확화
산출물
•	파이프라인 다이어그램을 글로 설명한 수준
•	기존 방법과 구조적으로 뭐가 다른지
•	이 논문만의 추상화 포인트
👉 이 workflow 없이 수식 Deep Dive는 실패 확률 높음
 
🔬 Workflow 4. 수식 & 개념 Deep Dive (Understanding Mode)
해결하는 문제
•	“DPR, BART, marginalization이 그냥 이름으로만 나온다”
•	“수식이 왜 필요한지 모르겠다”
•	“Adam, Beam Search를 다시 떠올려야 한다”
역할
•	수식을 사고 과정으로 복원
•	필요한 개념을 리프레시 형태로 설명
산출물
•	수식 등장 이유
•	변수 하나씩 의미
•	직관적 설명 (비유 포함)
•	관련 개념 리프레시
o	Adam / Beam Search / Marginalization
o	DPR / BART의 역할 정리
👉 ChatGPT가 가장 잘하는 영역을 극대화하는 workflow
 
📊 Workflow 5. 실험 결과 해석 (Why these results happened)
해결하는 문제
•	“숫자는 많은데 의미가 없다”
•	“왜 이 설정에서만 성능이 좋지?”
역할
•	실험을 가설 검증 관점에서 재해석
•	결과의 원인 설명
산출물
•	각 실험이 검증하려는 가설
•	성능 향상의 구조적 원인
•	결과 해석 시 주의점
👉 단순 SOTA 나열을 피하게 해줌
 
🚀 Workflow 6. 한계 · Future Research · 연결
해결하는 문제
•	“이 논문 이후 뭘 봐야 하지?”
•	“연구 방향이 안 보인다”
역할
•	한계를 선택의 결과로 해석
•	연구 갈래 제시
산출물
•	구조적 한계
•	가정이 깨질 경우 문제
•	명확한 future research 질문
•	후속 논문 추천
👉 논문을 ‘끝’이 아니라 ‘시작점’으로 만듦
 
(옵션) 🧑‍🏫 Workflow 7. Reader-Adaptive Refresher
언제 필요한가
•	독자 수준이 다양할 때
•	주니어/비전공자 대상
역할
•	논문에 등장하는 핵심 개념을 미니 강의처럼 설명
예시
•	“이번 논문에서 필요한 Adam만 다시 설명”
•	“이 논문을 이해하기 위한 Transformer 요약”
👉 메인 workflow를 오염시키지 않고 이해도 보정 가능
